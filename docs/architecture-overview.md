# Vela：本地 AI 网关与多供应商管理系统

## 一、项目概述

**基于 Go 的开源本地 AI 网关桌面客户端**，通过统一接入、多供应商调度和本地数据管理，解决 AI 使用中**渠道分散、密钥管理繁琐、上游不稳定、调用成本不透明**的问题。

用户将 AI 客户端连接到 Vela，即可集中管理不同供应商和模型，完成请求转发、故障切换、用量统计与费用估算。

## 二、核心设计理念

1. **本地优先**：配置、凭据和使用记录保存在本机，无需部署独立服务端或数据库。
2. **统一管理、原生接入**：统一管理不同渠道，保留 OpenAI、Anthropic、Gemini 各自的协议语义。
3. **调度与容错结合**：选路时兼顾优先级、会话亲和和成本，执行时结合限流、熔断和故障转移。
4. **调用全程可追溯**：从一次逻辑请求追踪到每次上游尝试，关联错误、耗时、用量和费用。

## 三、整体架构：模块化单体

**一个 Go 可执行文件承载桌面宿主、网关和业务核心**，按职责拆分模块；业务核心与桌面宿主分离。

```text
Vela
├── 桌面宿主：应用生命周期、菜单栏、后台运行、安装更新
├── 本机网关：统一鉴权、协议路由、流式与实时通信
├── 资源管理：供应商、多 Key、模型权限、映射与价格
├── 调度执行：候选排序、限流并发、重试、熔断与故障转移
├── 记录统计：调用明细、诊断、Token 用量与费用估算
├── 模型检测：可用性测试、指纹采样与参考库比对
└── 数据安全：SQLite 持久化、凭据加密、配置导入导出
```

## 四、核心模块职责

1. **本机网关**：提供 OpenAI Chat Completions / Responses、Anthropic Messages 和 Gemini 接口，支持普通响应、SSE 流式输出与 WebSocket 实时会话；覆盖工具调用、上下文压缩、Token 计数、向量、排序、图片、视频、搜索和文件能力。

2. **资源管理**：管理供应商和多个 API Key，通过模型权限与请求名映射衔接不同渠道；同步模型目录和价格，支持手动维护、本地修改保护及账户余额、倍率查询。

3. **调度执行**：提供固定顺序、会话亲和、成本优先三种策略；结合 RPM、并发限制、健康评分、熔断冷却和恢复试探，在上游异常时重试或切换候选。

4. **记录统计**：保留请求及每次尝试的结果、错误和耗时，解析不同协议的用量并估算费用；正文、明细与长期统计分别管理，支持查询和定期清理。

5. **模型检测**：执行模型可用性测试，复用 lm-detector 核心进行指纹采样、特征分析和参考模型排名，支持即时检测与计划任务。

6. **数据安全**：加密保存调用凭据和代理认证，通过密码加密文件迁移配置；使用事务、文件锁和原子替换保障数据一致性。

7. **桌面运行**：管理窗口、菜单栏、后台运行及网关暂停恢复，支持安装和经过签名校验的应用更新。

## 五、关键技术设计

- **选路与准入分离**：先按策略排列候选，再在实际调用前检查权限、凭据、速率、并发和健康状态，避免选中已经不可用的目标。
- **流式调用的安全重试**：区分“尚未交付结果”和“已经输出内容”，避免流中断后自动重放造成重复生成；按流式空闲时间判断超时。
- **有状态请求绑定**：续接、实时会话和资源操作绑定原供应商与 Key，防止切换目标后丢失上下文或无法访问原资源。
- **明细与统计解耦**：分别存储请求正文、调用明细和日聚合统计，兼顾问题排查、保留期限与长期成本分析。
- **凭据与配置分离保护**：本机凭据使用主密钥加密，跨机配置使用独立密码加密，导入后重新按本机密钥保存。

## 六、后端技术栈

- **语言与并发：Go**——使用 goroutine、channel、sync 和 context 处理并发请求、后台任务、超时取消与有序退出。
- **桌面宿主：MyGo**——提供类型化服务绑定、事件通知、系统交互和应用生命周期管理。
- **网络通信：net/http、SSE、coder/websocket**——实现 HTTP/TLS 接入、连接复用、流式输出及 Responses / Realtime 双向通信。
- **协议与传输：JSON、multipart、二进制流、gzip / deflate / zstd**——兼容结构化请求、媒体上传下载和压缩正文；zstd 使用 klauspost/compress。
- **网络出口：HTTP / HTTPS / SOCKS5 / SOCKS5h 代理**——统一控制上游请求、模型目录及账户查询的出网方式。
- **本地存储：SQLite + database/sql + modernc.org/sqlite**——以纯 Go 驱动免部署存储，结合事务、约束和索引保证一致性与查询能力。
- **加密与完整性：AES-256-GCM、PBKDF2-HMAC-SHA256、SHA-256**——分别用于凭据及配置加密、导出密码密钥派生、内容校验与摘要识别。
- **目录与缓存：Basellm / LiteLLM 数据源、ETag / Last-Modified**——同步模型和价格，通过条件请求及本地缓存减少重复下载。
- **模型指纹：lm-detector Go 核心 + go:embed 内置参考库**——通过统计特征评分和置信度校准，提供参考库内的模型相似性分析。
- **系统与交付：文件锁、原子文件替换、x/sys/unix、MyGo Updater、GitHub Releases**——保护本地数据访问，完成 macOS 安装和签名更新。
- **诊断与验证：标准日志、脱敏采集、testing / httptest、race detector、go vet**——支持故障追踪，以及真实调用链、并发和静态检查。

## 七、请求处理流程

```text
客户端请求
    ↓
本机网关鉴权 → 识别协议与模型 → 检查模型权限及映射
    ↓
按策略选择候选 → 检查限流、并发与健康状态
    ↓
调用上游供应商 → 返回普通 / 流式 / 实时响应
    ↓
记录执行结果 → 更新健康状态 → 结算用量与估算费用
```

可重试失败进入重试或故障转移；已交付生成结果、有状态绑定等情况遵守各自的重放与目标约束。

## 八、项目亮点与当前边界

- **轻部署**：桌面应用内集成网关和数据库，无需独立部署后台服务。
- **多渠道统一调度**：将供应商管理、模型权限、会话亲和、成本选择和故障恢复串成完整调用链。
- **生成与实时通信统一管理**：HTTP、SSE 和 WebSocket 复用配置、调度约束及记录能力。
- **成本与渠道质量可观察**：结合调用追踪、费用估算和模型指纹，辅助判断渠道表现。

当前公开安装包支持 **macOS 14+、Apple Silicon**，网关仅监听本机并随应用运行。各协议按原生格式接入，不做跨协议转换；远端兼容性取决于供应商实现。费用属于估算，指纹结果属于统计参考，续接与资源绑定仅在当前进程有效。
