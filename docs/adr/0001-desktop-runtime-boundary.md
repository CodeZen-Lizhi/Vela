# 0001：桌面运行时与业务边界

- 状态：已采纳
- 日期：2026-11-09

## 背景

Aether 重构需要缩小安装包、启动时间和常驻内存，同时保留完整桌面管理能力与本机 HTTP 网关。现有 Rust、Tauri 与 Vue 组合存在可迁移能力，但重构允许重做应用边界与前端技术栈。

## 决策

使用一个 Go 可执行文件承载 MyGo 桌面宿主和应用服务，并为后续本地网关保留边界。前端使用 Svelte 5、TypeScript、Vite、Tailwind CSS 4 和 shadcn-svelte，通过 MyGo 生成的类型化客户端调用 Go 服务。

业务核心不依赖 MyGo，桌面入口只负责窗口生命周期与系统能力。当前入口位于 `cmd/vela`，后续网关、数据与调度模块应放在独立 Go 包中，为未来独立运行入口保留边界。

## 影响

- 当前脚手架没有网关业务实现；后续接入网关时必须验证长流式请求、退出和重启不会互相阻塞。
- 系统 WebView 仍可能创建独立系统进程，单个 Go 可执行文件不代表只有一个操作系统进程。
- 前端只通过类型化绑定调用应用服务，不绕过 Go 直接访问业务数据。
- 首期仅交付 Apple Silicon macOS；跨平台能力保留，但不作为当前验收范围。

## 验证

正式重构需要以真实 MyGo 窗口验证启动、内存、长表格、中文输入、流式请求、退出与打包行为。当前脚手架只验证依赖初始化、类型生成、桌面壳启动和构建链路。
