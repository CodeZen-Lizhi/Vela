# 0003：标准 Responses WebSocket 与同格式执行边界

- 状态：已采纳
- 日期：2026-11-12

## 背景

供应商的 Responses WebSocket 开关原来只有配置和页面，缺少真实消费者。Aether 已有原生标准桥接、物理连接绑定、逐轮准入及退出清理，Vela 需要保留这些页面不可见的行为。

## 决策

- `GET /v1/responses` 使用同一网关密钥升级；只有显式启用 WebSocket 的供应商参与候选，HTTP/SSE 请求继续使用 HTTP。默认关闭，失败不偷偷改用 HTTP 或其他协议。
- 使用 `github.com/coder/websocket v1.8.15` 处理协议帧、控制帧和取消，避免自研 RFC 6455。它是 `x/net/websocket` 自身推荐的活跃替代，支持复用现有 HTTP 客户端、TLS 与代理，且没有额外传递依赖。
- 每个客户端连接持有一个上游标准 Responses 会话，逐轮经过原执行器复核认证、模型/权限、Key、凭据版本、映射、出口、RPM、并发和健康。已有绑定不得透明换目标；绑定验证失效时返回 409 并断开连接，提示重新连接后使用完整历史发起请求，不通过清空绑定恢复选路。读循环覆盖生成和空闲期，处理 Ping/Pong。公开 response.created 状态后不透明重放。
- `response.create` 是逻辑记录及结算单位。复用 R52 和记录观察器；原始 JSON 事件只在内部以 SSE 形状用于有界采集，不改变双端 WS 文本帧。真实握手状态保留 101，传输独立标为 websocket。明确 generate:false 的预热不要求模型内容、健康中性。
- 沿用 Aether 默认通道、16 MiB 消息、首帧 60 秒、连接 1 小时和写入 30 秒边界。单轮等待采用供应商流式空闲超时配置；每次上游数据重新计时，持续输出不按累计总时长中断（2026-11-15 用户确认）。HTTP Shutdown 不负责升级后的连接，网关单独跟踪、取消并在关闭预算内等待清理，随后宿主才关闭数据库。
- 命名 stream_id、私有原生账号扩展和跨格式转换不在当前标准中转站范围；不支持的事件/通道明确报错。

## 验证与限制

`internal/app/websocket_test.go` 通过真实客户端和严格本地上游，覆盖连接复用与工具往返、记录用量、开关、权限、代理、重试边界、预热、空闲控制帧、暂停及断连清理。目标供应商与真实 Codex Desktop 的最终组合仍需单独验证；本地上游验收不等同于所有供应商均兼容。
