# Vela 0.1.0-beta.1

版本性质：公开测试版。目标为 macOS 14+、Apple Silicon（arm64）；本次不提供 Intel、Windows 或 Linux 安装包。MIT 许可已确认。

[返回 README](../../README.md) · [Releases 下载页](https://github.com/CodeZen-Lizhi/Vela/releases) · [交付证据与待验收项](../public-beta-delivery.md)

## 下载与首次安装

从 Releases 对应版本的资产区下载 `vela-0.1.0-beta.1-arm64.dmg`，另提供 `vela-0.1.0-beta.1-arm64.app.zip`。大小与 SHA-256 以同批 `release-manifest.json` / `SHA256SUMS` 和交付记录为准；发行标签为 `v0.1.0-beta.1`，以对应 Release 页面中的资产为准。

App 采用 ad-hoc 签名，未经过 Apple Developer ID 签名或 Apple 公证；ad-hoc 签名不代表 Apple 已验证开发者身份。

1. 核对下载来源与校验值，打开 DMG，双击其中的 `Vela.app`，选择“安装并打开”。从只读安装卷启动会在数据初始化和单实例检查前进入原生安装确认；普通已安装或开发启动不进入该流程。取消时退出介质中的进程，不访问用户数据。
2. 安装器先复制并校验新版，再正常退出 `/Applications/Vela.app`；等待网关及记录收尾后替换整包，清除旧包遗留文件并打开新版。30 秒仍未退出会停止安装，不强杀或覆盖旧版。其他路径的副本不自动退出，现有数据目录保留。权限不足时由系统请求管理员授权；安装完成但自动启动失败时，可从“应用程序”手动打开。
3. 若 macOS 阻止打开，核对来源后到“系统设置 → 隐私与安全性”按提示选择“仍要打开”。若仍提示损坏或拒绝运行，保留原提示并核对校验值，不要关闭 Gatekeeper、禁用 SIP 或批量移除隔离属性。不同电脑首次安装的提示可能不同。

仍可自行退出旧版后拖拽安装。后续版本需要手动下载安装包；应用内更新入口位于“设置 → 常规 → 应用更新”：手动检查，下载校验后确认重启；本轮已接入，官方公开更新源为 `CodeZen-Lizhi/Vela` 的 Releases；当前相同版本不会重复升级，后续更高版本的更新包由内置公钥验证。

## 完成首次真实调用

按 [README 快速上手](../../README.md#快速上手完成第一个-chat-请求) 创建对话模型、供应商、上游 Key、关联及权限。首次还须在“设置 → 接入与访问”的“网关接入”点击“设置密钥”，填写并“保存密钥”，应用不会自动生成。若默认 18080 被占用而提示密钥已保存但网关未生效，修改端口后点击“保存端口”重试，再用网关密钥调用 `POST /v1/chat/completions`。

验收应同时观察 HTTP 200、真实上游回答和“使用记录”中的对应请求；模型列表和健康接口不调用上游。启用网关、手动模型测试、指纹检测与定时计划均可能产生真实上游费用，请使用自己的有效额度。本版候选包已通过本机可控上游 Chat 与持久化检查，远端付费供应商仍需按自己的服务实测。

## 协议入口与兼容边界

根地址默认为 `http://127.0.0.1:18080`，实际端口以“设置 → 接入与访问”为准。所有业务入口都需要网关密钥，Bearer 适用于下列入口；Messages 也接受 `x-api-key`，Gemini 也接受 `x-goog-api-key`（兼容 `key` 查询参数，建议使用请求头以减少 URL 泄露）。健康和模型清单同样需要鉴权。

| 用途 | 路径 |
| --- | --- |
| 健康与模型清单 | `GET /v1/health`、`GET /v1/models` |
| Chat Completions | `POST /v1/chat/completions` |
| Responses / Compact | `POST /v1/responses`、`POST /v1/responses/compact` |
| Messages / Token 计数 | `POST /v1/messages`、`POST /v1/messages/count_tokens` |
| Gemini 对话 / Token 计数 | `POST /v1beta/models/{model}:generateContent`、`:streamGenerateContent`、`:countTokens`，也接受 `/v1/models/` |
| 向量 / 排序 | `POST /v1/embeddings`、`POST /v1/rerank`；Gemini `/v1beta/models/{model}:embedContent`、`:batchEmbedContents`（也接受 `/v1/models/`） |
| 图片 | `POST /v1/images/generations`、`POST /v1/images/edits` |
| 视频 | `POST /v1/videos`；`GET /v1/videos/{id}`、`GET /v1/videos/{id}/content`、`DELETE /v1/videos/{id}` |
| Search | `POST /v1/alpha/search` |
| Gemini Interactions | `POST /v1beta/interactions`；`GET/DELETE /v1beta/interactions/{id}`，也接受 `/v1/interactions` |
| Gemini Files | `POST /upload/v1beta/files`、`GET /v1beta/files`、`GET/DELETE /v1beta/files/{id}`；分段上传使用网关返回的本机上传地址 |
| Responses WebSocket | 升级 `GET /v1/responses`，即 `ws://127.0.0.1:18080/v1/responses` |
| 标准 OpenAI Realtime | 升级 `GET /v1/realtime?model={model}` |

这些路径已在源码中接入，不代表所有远端供应商均支持或已通过安装包组合验收。同格式转发不做跨协议转换，各入口仍要求正确模型类型、关联、Key 权限和上游支持；Files 根据已配置能力选路。Gemini 流式返回使用 SSE，客户端应按其原生协议填写参数。

Responses WebSocket 发送标准 `response.create`，供应商高级设置中的 WebSocket 开关默认关闭，须先启用；普通 HTTP/SSE 不受此开关影响。仅支持默认通道，命名 `stream_id` 被明确拒绝；不包含私有原生账号适配或 Codex Live。

视频创建在同一 Key 内轮询至终态，不能将 queued/in_progress 视作生成成功；超时或失败时不要盲目重试创建。Responses HTTP `background:true` 未接入异步查询契约，出站前返回 400。

Responses 的 `previous_response_id`、视频、Gemini 文件/上传与 Interactions 依赖当前进程的原执行目标绑定；重启、到期、容量淘汰或原认证/地址/模型映射变化后，未知或不可验证的资源返回 409，不会改选其他 Key。保存响应 ID 或复制文件名不能实现跨进程续接；重启前应完成仍需继续的资源操作。

## 本地数据、费用与指纹

默认数据目录为 `~/Library/Application Support/Vela/`，开发时可通过 `VELA_DATA_DIR` 隔离。网关密钥、上游 API Key、账户认证和代理凭据仅在本机加密保存；请求内容与必需认证仍发送到用户配置的上游，目录和账户查询按各自设置联网。

正文从请求结束起保留 7 天，请求明细与诊断保留 30 天，累计统计独立保留；进行中请求不按期限清理。没有正文采集开关、更多采集项或可编辑期限；媒体二进制和完整内嵌 base64 不落入请求正文。手动清理须预览并确认，保留配置、凭据、验证报告及累计统计。日志与手工保全的旧文件不因此获得安全擦除保证。

费用来自上游可用用量与本地价格快照的估算，不是供应商账单；缺失用量或价格保持未知。指纹检测只衡量固定参考库内的统计相似性，不认证模型身份，也不能单凭差异认定渠道造假；采样调用会消耗真实额度，取消无法撤回已产生的费用。

## 升级与应急恢复

应用不提供整库备份/恢复功能，配置导入导出目前也尚未实现。以下仅为同一台电脑在升级失败时恢复原文件的人工应急步骤，不用于跨机搬运配置或保证新旧版本数据库兼容。

1. **保全应急文件前真正退出 Vela。** 使用应用或菜单栏的“退出 Vela”，确认进程已结束；关闭窗口可能仍在后台运行。从 DMG 双击自安装会正常退出目标安装版；如需执行下述原文件保全步骤，仍须先手动退出再复制。不要同时运行安装版与共用同一数据目录的开发版。旧版若尚未实现数据目录锁，不能由新版锁强制阻止其并行写入，因此升级前必须先退出旧版。
2. 在应用退出后，手工将原数据目录完整复制到自己控制、受保护的位置。默认路径为 `~/Library/Application Support/Vela/`；若设置过 `VELA_DATA_DIR`，以实际目录为准。保留目录内所有原文件，包括 `vela.sqlite`、可能存在的 SQLite 辅助文件及完整 `credentials/`；不要在应用运行时只复制数据库。
3. 主密钥 `credentials/master.key`、`credentials/secrets.enc` 和数据库内的密文必须来自同一份原文件。目录权限应为 0700、凭据文件为 0600。取得主密钥和密文即可解密，不要上传该目录、公开日志或把副本存到公共共享位置。
4. 从 DMG 双击安装后会自动启动；手工替换应用则自行启动，确认版本、供应商/模型/Key 配置和一次真实 Chat 调用，再决定是否继续使用。本次已用本机 `0.1.0` 安装包和隔离样例验证原配置、凭据和历史保留；不代表任意历史版本均兼容。
5. 如启动失败或需要回退，退出所有 Vela 进程，先保留失败时的数据目录及错误证据，再将原来保全的文件作为一组恢复到原位置，并使用与原数据对应的旧应用打开。不要合并新旧数据库、单独替换主密钥或在原文件上反复试验。恢复原文件会丢弃升级后新增的本地更改与记录，无法撤回上游调用或费用。
6. 若没有匹配的原文件或主密钥已丢失，停止覆盖操作。新建空密钥不能解密原数据；不要删除原目录来“修复”启动错误。

## 启动失败与反馈

应用将诊断日志保存在实际数据目录的 `vela.log` 与 `vela.previous.log`（本次与上次启动），启动失败用原生弹窗显示原因及相关路径。若日志尚未创建，先保留弹窗中的原因与路径。

反馈可通过 [GitHub Issues](https://github.com/CodeZen-Lizhi/Vela/issues) 提交系统版本、芯片类型、应用版本、操作步骤与脱敏后的错误片段。凭据、主密钥、完整数据库、完整请求正文与未经检查的日志只留本机；不要直接上传整个数据目录。

## 已知未完成与验收状态

配置导入导出尚未实现；应用内更新已接入本地签名构建和隔离验证，远端发布尚未上线；20 并发与 100 万条历史规模未验收，启动、内存及包体积没有本次已通过的性能结论。本机下载、包内容、原生窗口、配置持久化、Chat 调用、升级恢复及生命周期检查的实际覆盖见交付记录；未覆盖的系统和远端组合保持待验证。
