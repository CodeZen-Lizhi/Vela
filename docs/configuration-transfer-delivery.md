# 配置导入导出交付

- 日期：2026-11-15。
- 需求依据：Aether `docs/tasks/11-07-desktop-rewrite/plan.md` 的 R45、R53、第 5.13 节和 A11，已同步本次确认的完整认证搬运与两种合并方式。
- 入口：设置 → 数据管理 → 导入与导出。

## 实现

配置文件包含模型及完整价格/来源/修改保护、供应商请求配置、上游 Key、模型关联/映射/权限、余额与 Key 查询的实际认证及字段路径、调度策略与供应商顺序。完整秘密只在后端解密边界使用，页面仅接收加密文件和预览数量。

导出设置文件密码，使用 PBKDF2-HMAC-SHA256（600000 次、随机 16 字节盐）与既有 AES-256-GCM 实现加密，原生保存对话框选择目标，0600 临时文件写入同步后原子替换。v1 限制为 5 MB，不接受原型快照、整库备份或未知版本；源机器主密钥与本机网关访问密钥不进入文件。密码不持久化，导入时使用目标机器凭据重新加密。

导入提供“覆盖相同配置”和默认的“保留原有、仅新增”。模型、供应商、Key 匹配时保留本机稳定身份，并重映射关联与权限；映射按请求名合并，本机独有请求名保留。保留模式会补齐缺少的关联、映射及 Key 查询连接，已有主体和查询配置保持本机值。调度覆盖时采用来源策略和顺序后追加本机独有项，保留时沿用已保存策略和顺序、追加新增供应商；空实例采用来源策略。

全部资源在同一 SQLite 事务内提交；取消、校验失败或写入中途失败不留下部分资源。导入不写请求历史、正文、统计、验证报告、本机偏好或网关密钥。既有历史名称跟随当前资源改名的规则继续有效；不重新结算历史费用。

## 边界

支持正式 Vela v1 密码加密配置文件，不兼容旧原型的合成配置包。验证使用隔离的合成认证和真实本机 HTTP 上游，未使用用户真实账户；本次没有提交、发布或替换已安装应用。
